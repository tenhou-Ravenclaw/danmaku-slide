# 透過ウィンドウシェル（貼り方C）

スライドの上に透過ウィンドウを重ねる。**このシェルは弾幕を描かない。**
配信済みの弾幕ページを透過ウィンドウで開くだけ。描画の実装を1本に保つのが
このプロダクトの設計なので、ここに描画を持たせない。

## 手早く試す

```bash
npm run shell
```

## 配布するものを作る

```bash
npm run pack:app
```

`dist/` に `.app` と zip ができる。**署名していないので、macOS では初回だけ
右クリック →「開く」** が要る（ダブルクリックだと「開発元を確認できない」で止まる）。

開発中に別の配信先を見たいときは `DANMAKU_ORIGIN` で差し替える。

```bash
DANMAKU_ORIGIN=http://127.0.0.1:5055 npm run shell
```

## 操作

| | |
|---|---|
| トラックID または 投稿URL | QR の URL をそのまま貼ってもいい |
| `danmaku://track/xxx` のリンク | 運営のリンクから起動すると**貼らずに入る** |
| 流す画面 | 拡張ディスプレイを繋いでいるときは投影先を選ぶ |
| 「終了する」 | アプリを終える |
| <kbd>⌘⇧X</kbd> / <kbd>Ctrl+Shift+X</kbd> | 「終了する」と同じ |

クリックは**必ず下へ通す**。弾幕の上からスライドをそのまま操作できる。切り替える口は置かない。

この窓には押せるものが1つも無い（操作バーは透過のとき `display: none`）。
受け取るようにすると、画面全体を覆う窓が何もせずクリックを飲み込むだけで、
スライドにも設定ウィンドウにも手が届かなくなる。切る理由が無いものを切れるようにすると、
詰む経路だけが増える。

キーは <kbd>⌘⇧X</kbd> だけ残してある。全画面のスライドショー中は窓が後ろに隠れるので、
手が届かないまま終われる道が要る。
送り先は設定ウィンドウだけ。透過ウィンドウはリモートの弾幕ページを読んでいるので、
preload を持たせていない。

## リンクから起動したとき

**入力欄は使わない。** 欄の中に `b52bj39v a` と並ぶと、受け取れたのではなく
自分が貼り間違えたように見える。受け取れた事実と、受け取ったイベント／トラックを
分けて出し、貼る欄そのものを引っ込める。

手で貼る経路（ID / 投稿URL / `danmaku://` を `parseTrackId` に通す）は変えていない。
受け取ったぶんも同じ入口を通している。

## 設定ウィンドウは消えない

重ね始めても設定ウィンドウは隠さない。**止める手段がこのウィンドウの中にしか無い**ので、
隠すと「出すには止める、止めるには出す」になって手が1つも残らない
（`app.dock.hide()` しているので Cmd+Tab にも出てこない）。

| 画面の数 | どうなるか |
|---|---|
| 1枚 | スライドの全画面に覆わせる。全画面を切れば出てくる |
| 2枚以上 | 投影先**でない**画面の真ん中へ自分で逃げる。客席に映らないまま手元で触れる |

弾幕のウィンドウは `screen-saver` レベルで最前面に居るので、設定ウィンドウに
隠されることはない。透過ウィンドウは `focusable: false` なので、
設定ウィンドウを触ってもフォーカスの奪い合いは起きない。

## なぜこの設定なのか

この組み合わせが貼り方Cの本体で、**どれか1つ外れただけで全画面のスライドショーの
上に残らなくなる**。`test/shell/parse.test.mjs` で設定そのものを固定してある。

| 設定 | 理由 |
|---|---|
| `setAlwaysOnTop(true, 'screen-saver')` | `floating` や `normal` では PowerPoint や Keynote の全画面に負ける |
| `setVisibleOnAllWorkspaces(true, { visibleOnFullScreen: true })` | macOS の Space をまたぐ |
| `fullscreenable: false` | 全画面にすると OS が別の Space を作り、スライドの上に出られなくなる |
| `focusable: false` | フォーカスを取るとスライドショーが一時停止する |
| `backgroundThrottling: false` | 画面が隠れると描画が止まり、弾幕が固まる |
| `transparent: true` + `backgroundColor: '#00000000'` | 背景を抜く |
| `app.dock.hide()` | Dock に出るとフォーカスを取ってしまう場面がある |
| `enableLargerThanScreen: true` | これが無いと macOS がメニューバーのぶん押し下げ、画面の上端が覆えない |

## PowerPoint が前に出てくる件

PowerPoint のスライドショーは**自分を最前面に主張し続ける**ので、一度重ねても
しばらくすると裏に回ることがある。1.5秒ごとに押し戻している。

```js
overlayWin.setAlwaysOnTop(true, 'screen-saver');
overlayWin.moveTop();
```

奪い返すのは重なり順だけで、**フォーカスは取らない**。フォーカスを取ると
スライドショーが一時停止してしまう。

それでも負ける場合の逃げ道が3つある。

1. **閲覧表示（Reading View）で出す。** 通常ウィンドウになるので最前面を主張しない
2. **PowerPoint を投影先ではない画面に置く。** 投影先には弾幕だけを重ねる
3. **貼り方B（キャプチャ合成）に切り替える。** 最前面の奪い合いが起きない

## Electron を選んだ理由

Tauri も検討したが、macOS で同じことをするには Rust と AppKit のシムを書いたうえで
`macOSPrivateApi` を有効にする必要があり、Electron の2行と釣り合わない。
WKWebView になることで、ここまでの検証をやり直すことにもなる。

配布サイズは Electron のほうが大きいが、**このアプリは登壇者1人が自分の端末で
動かすもの**で、配布サイズが使われるかどうかを左右しない。
